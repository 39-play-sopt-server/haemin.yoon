# 회원과 게시글 작성자

## API 사용 순서

1. `POST /members`에 `{"name":"홍길동"}`을 보내 회원을 생성합니다.
   HTTP 201과 공통 응답의 `data: {"id":1,"name":"홍길동"}`을 반환합니다.
2. 반환받은 회원 ID를 `POST /posts`의 `memberId`로 전달합니다.
   `{"title":"첫 글","content":"본문","category":"GENERAL","memberId":1}`
3. `GET /posts`의 `data.items`와 `GET /posts/{id}`의 `data`는 `author` 응답 필드에 참조 회원의 이름을 표시합니다.
4. `DELETE /members/{id}`는 HTTP 200과 공통 성공 응답(data=null)을 반환합니다.

이름은 공백뿐인 값을 허용하지 않으며 UTF-16 코드 단위로 50자까지 허용합니다.
NUL 문자는 `MEMBER_NAME_NUL_NOT_ALLOWED`로 거부하고 다른 공백·문자는 보존합니다.
이름은 식별자가 아니므로 동명이인을 허용합니다. 회원 ID가 회원을 식별합니다.
없는 회원이나 이미 삭제된 회원의 삭제·새 글 작성은 HTTP 404 `MEMBER_NOT_FOUND`입니다.
`memberId` 누락·null·0·음수는 HTTP 400이며, 소수도 정수로 절삭하지 않고 거부합니다.
예전 `author` 문자열만 보내는 생성 요청은 필수 `memberId`가 없어 실패합니다.

## 구조와 삭제 정책

- `member` 도메인이 이름 검증과 소프트 삭제 정책, 회원 포트·서비스·저장소·API·문서를 소유합니다.
  입력 포트는 `port/in/command`·`port/in/query`, 웹 DTO는 `dto/request`·`dto/response`로 구분합니다.
  회원 전용 실패는 `MemberErrorCode`만 받는 `MemberException`으로 전달합니다.
  신규 저장 포트는 ID가 없는 회원만 허용하고 기존 회원의 변경은 JPA 변경 감지로 처리합니다.
- `Member`는 `BaseEntity`를 상속하고 `id`, `name`, `deleted`를 관리합니다.
  `MemberCommandService`는 쓰기 트랜잭션에서 생성·삭제를 담당하고,
  `MemberQueryService`는 읽기 전용 트랜잭션에서 활성 회원 조회를 담당합니다.
  두 서비스는 서로 호출하지 않고 출력 포트를 사용합니다. `LoadMemberPort.findActiveById`가
  삭제된 회원을 제외하는 조회 계약을 정의하므로 활성 회원 필터가 서비스마다 중복되지 않습니다.
- `PostCommandService`는 회원 입력 포트인 `MemberQueryUseCase`로 활성 회원을 확인합니다.
  회원 저장소를 직접 호출하지 않으며 게시글 생성과 회원 확인은 같은 트랜잭션에 참여합니다.
- `Post.member`는 필수 단방향 `@ManyToOne(fetch = LAZY)`입니다.
  `posts.member_id`에 NOT NULL·외래 키·인덱스를 적용하고 작성 후 회원 변경을 허용하지 않습니다.
  회원에서 게시글로의 역방향 컬렉션이나 cascade는 추가하지 않습니다.
- 삭제는 회원 행의 `deleted`를 true로 변경합니다. 회원 행과 게시글을 보존하며 기존 글은
  삭제된 회원의 이름도 계속 표시합니다. 삭제된 회원은 새 글을 작성할 수 없습니다.
- 목록은 EntityGraph, 단건은 fetch join으로 회원을 함께 로드합니다.
  트랜잭션 종료 뒤 DTO로 변환해도 이름을 읽을 수 있으며 목록의 N+1 조회를 방지합니다.
  조회수 벌크 갱신은 이미 로드한 게시글만 refresh하고 아직 읽지 않은 게시글은 다음 조회에서 회원과 함께 읽습니다.
- 회원 오류와 OpenAPI 응답은 회원 도메인이 등록합니다. 전역 오류 핸들러·문서 설정은 변경하지 않습니다.

## 기존 데이터와 배포

V6은 members 테이블을 생성하고 기존 게시글의 author를 회원 이름으로 복사합니다.
기존 이름만으로 동일인 여부를 판단할 수 없어 게시글마다 독립된 회원을 만듭니다.
게시글 ID·내용·조회수·버전·생성일·수정일을 보존하고, 회원의 시각도 해당 게시글 시각으로 초기화합니다.
모든 글의 member_id를 연결하고 제약을 적용한 뒤 author와 임시 매핑 컬럼을 제거합니다.
회원 이름의 새 입력 검증은 기존 데이터를 읽거나 마이그레이션할 때 소급 적용하지 않습니다.

V6 적용 이후 기존 author 컬럼으로 쓰는 구버전 서버는 호환되지 않습니다.
구버전 쓰기를 중단하고 마이그레이션·서버·클라이언트 요청 전환을 함께 적용해야 합니다.
현재 로컬 DB에는 직접 마이그레이션하지 않으며 애플리케이션 시작 시 Flyway가 적용합니다.

## 범위와 확장

현재 기능은 회원 등록·탈퇴와 게시글 작성자 연결입니다. 로그인·인증·작성자 권한 검사는 제공하지 않습니다.
앞으로 인증을 추가한다면 검증된 로그인 회원 ID를 게시글 생성에 전달하도록 입력 경계를 변경합니다.
회원 이름 변경을 추가한다면 회원 도메인에 수정 유스케이스를 추가하면 되며 기존 글에도 현재 이름이 표시됩니다.
작성 당시 이름을 보존해야 한다면 게시글에 별도 이름 스냅샷 정책이 필요합니다.
완전 삭제·익명화가 필요해지면 회원 참조와 보존 정책을 함께 변경해야 합니다.
